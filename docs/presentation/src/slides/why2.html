결과 4 · 원인 분석 (2) 왜 빨라졌나

한도를 올리면 작업이 빨라지는 게 아니라 기다림이 없어진다

자기 파일을 실제로 처리한 시간

줄 서서 기다린 시간

한도 512 MiB

9.5초 · 작업 0.8초 + 대기 8.7초

한도 2 GiB, 첫 1분

0.5초 · 작업 0.5초 + 대기 거의 0

창구가 여러 개가 된다

2 GiB에서는 snapshot 하나의 파일 7개가 동시에 올라갈 수 있다. 예약 합계 2,056 MiB가 한도와 거의 같다.

작업 시간은 비슷하다

자기 파일을 처리하는 시간은 0.8초와 0.5초로 큰 차이가 없다. 줄어든 9초는 거의 전부 대기 시간이다.

요청을 다 처리한다

첫 1분 동안 목표인 초당 1회를 처리했다. 기본 한도에서는 초당 0.7회에 머물렀다.

출처: 자체 측정 (2026년 11월). 업로드 구간의 중앙값. 작업 = 그 snapshot에서 가장 오래 걸린 파일의 처리 시간

두 번째 장은 왜 빨라졌는가입니다. 업로드 플러그인은 한도를 얻은 뒤부터의 시간을 파일마다 기록합니다. 그래서 업로드 구간을 실제로 처리한 시간과 줄 서서 기다린 시간으로 나눌 수 있습니다. 회색이 실제 처리 시간, 주황색이 기다린 시간입니다. 기본 한도에서는 9.5초 가운데 처리가 0.8초, 대기가 8.7초입니다. 한도를 2 GiB로 올린 첫 1분은 0.5초이고 대기가 거의 없습니다. 2 GiB에서는 snapshot 하나의 파일 일곱 개가 동시에 올라갈 수 있기 때문입니다. 창구가 여러 개가 된 셈입니다. 여기서 중요한 점은 실제 처리 시간이 0.8초와 0.5초로 크게 다르지 않다는 것입니다. 한도를 올렸다고 일이 빨라진 것이 아니라, 기다림이 없어진 것입니다. 그 결과 첫 1분 동안은 목표였던 초당 1회를 다 처리했습니다. 기본 한도에서는 초당 0.7회에 머물렀습니다.
